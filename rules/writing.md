# 書き方の規則（ingest / lint 共通）

## 要約ページ（`templates/source-page.md`）
- パス: `wiki/sources/<source_id>/<公開日>-<slug>.md`。`published: unknown` のページは、ファイル名の日付に取得日を使う。ファイル名は小文字の英数字とハイフン。
- 必須フロントマター: `type, source_id, title, url, published, retrieved, tier: primary, review: pending`。任意: `version, fingerprint, recheck, archive_url`。
- 本文: `## 要点`（3〜7行）、`## 具体的な値`（コマンド、フラグ、設定キー、環境変数、数値、バージョンを**原文表記のまま**）、`## 関連ページ`、`## 取り込みメモ`（取得できなかった部分、不確かな点）。
- 記事の一覧ではなく、記事のページ本体を読む。
- CHANGELOG とリリースノートは、前回からの分を1ページにまとめる。拾うのは、機能追加、仕様変更、設定名、非互換、セキュリティ関連。細かい修正は「その他の修正が N 件」と数でよい。CHANGELOG の `published` には、バッチ内で最新の版の npm 公開日時を使う。

## 概念ページ（`templates/concept-page.md`）
- 必須フロントマター: `type, title, updated, sources`。本文: `## 概要`、`## 現状（as of YYYY-MM-DD）`、`## 変更履歴`（新しい順）、`## 未解決・矛盾`。
- 本文の事実には、その場で `（[[sources/...]]）` を付ける。出典の無い断定は書かない。
- 1つの資料でしか触れられていない些末な語のために、ページを作らない。
- リンクは `[[sources/<id>/<file>]]` の形（wiki/ からの相対パス、拡張子なし）。

## 食い違いの扱い（close, never delete）
- 古い記述は消さない。`## 変更履歴` に「いつ・何が・どう変わったか」を残し、`## 現状` を更新する。
- **出典の優先順位**: 価格は `pricing`、仕様と提供範囲は `docs`（Claude Code）と `platform-docs`（Claude API 側）を正とする。ブログや記事と食い違ったら、まずこれらを確かめ、記載があれば採用する。記事の値は「公開時点の値」として扱う。
- これらに記載が無いときだけ、`## 未解決・矛盾` に両方の出典を付けて残す。解決したら消さずに「解決済み」と書いて閉じる。

## 要約の規則
- 自分の言葉で要約する。引用は15語未満で、1つの情報源につき1回まで。
- 事実と推測を分け、推測には「（推測）」と書く。
- 日付と日時はすべて JST で書く。情報源が時刻付きの UTC（npm の `time` など）を示すときは JST に換算し、表の見出しなどに「JST」と書く。時刻の無い日付は、情報源の表記のまま使う。
- `published`（情報源が示す日付）と `retrieved`（取得日、JST）を区別する。日付が読み取れなければ `published: unknown` とし、理由を取り込みメモに書く。年が省略された日付は、記事の公開年で補ってよい（補ったことを取り込みメモに書く）。
- ベータ、研究プレビュー、early access などの段階は必ず書き、`recheck: weekly` を付ける。
- 削除は人間の指示があるときだけ。
