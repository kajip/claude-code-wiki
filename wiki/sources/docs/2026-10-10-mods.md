# Mods overview（Claude Code ドキュメント）

## 要点

- mod は「Claude Code の見た目と動きを変えるプラグイン」。中身は JS／TS のイベントハンドラ（hook）で、Claude Code のプロセス内で動く。設定ファイルの hook（シェル／HTTP／プロンプト）とは別物で、docs ではそちらを「settings hook」と呼んで区別する。
- できること: ペイン／プロンプト上の帯の描画、既存 UI（ツール行、スピナー、質問ダイアログ）の差し替え、ツール呼び出しやリクエストへの介入、`/command` の追加、hook 間での変数共有。
- 最小構成は3ファイル（`plugin.json`、`hooks/hooks.json`、`hooks/register.js`）。`hooks.json` の `modules` に1つのパスを書くと、そのプラグインが mod になる。ビルド手順は不要で `.js`／`.ts` を直接読む。
- 各 hook は `($, e, next)` を受け取る。`$` は mods API、`e` は凍結されたイベント、`next` は次のハンドラ。「観察（`next(e)`）」「書き換え（コピーを `next` に渡す）」「答える（`next` を呼ばずに結果を返す）」の3通り。
- mod は**サンドボックス外**で、ユーザーと同じ権限で動く。権限プロンプトの表示だけは変えられない。管理者向けには `allowManagedModsOnly` などの制御がある。
- ターミナル 2.1.287 以降（Desktop アプリは 2.1.286 以降）で既定有効。ベータ等の段階表記は docs に無い。ただし API は版ごとに変わりうるため、書き出される型定義を正とする。

## 具体的な値

### ファイル構成と plugin.json

- 必須の3点: `.claude-plugin/plugin.json`（必須）、`hooks/hooks.json`（必須）、hooks モジュール（必須。`.js .mjs .cjs .jsx .ts .mts .cts .tsx`、ES module）。`types/index.d.ts` は `$.state` を使うか API に namespace を足すときに必要。`*.test.ts`／`*.test.tsx` はテスト（任意）。
- `hooks.json` の最小形: `{ "description": "...", "modules": ["./register.js"] }`。`modules` は `hooks.json` からの相対パスの配列（1件）。同じファイルの `hooks` キーに settings hook も置ける。
- モジュールは `export function register(on, options)` を持つ。`options` は manifest の `userConfig` の値（既定値込み）。
- plugin.json のトップレベル全フィールド（`name` のみ必須）: `$schema`、`name`、`displayName`、`version`、`description`、`author`（`name` 必須、`email`、`url`）、`homepage`、`repository`、`license`、`keywords`、`metadata`、`icon`、`documentationUrl`、`supportUrl`、`privacyPolicyUrl`、`termsOfServiceUrl`、`defaultEnabled`（既定 `true`）、`dependencies`、`settings`（効くのは `agent` と `subagentStatusLine` のみ）、`userConfig`、`types`（mod 用。`$.state` と `$` の名詞を宣言する `.d.ts`）、`channels`、`skills`、`commands`、`agents`、`hooks`、`mcpServers`、`lspServers`、`outputStyles`、`workflows`、`experimental`（`themes`、`monitors`、`evals`）。mods は必須フィールドを足さない。
- 未知のトップレベルキーは捨てられて読み込まれる（`validate` は警告）。`userConfig` の項目、`channels`、`lspServers`、`monitors` の中の未知キーはエラーでプラグインが読み込まれない。
- `userConfig` の各項目: `type`（`string`／`number`／`boolean`／`directory`／`file`）、`title`、`description`（この3つは必須）、`required`、`default`、`options`（v2.1.271 以降）、`multiple`、`sensitive`、`min`／`max`。値は `pluginConfigs` に、キーは plugin の id か、`--plugin-dir` で読んだものは `名前@inline`。
- `name` の予約: `claude-`／`anthropic-`／`anthropics-`／`cc-plugin-` で始まる名前、`claude`、`anthropic`、`anthropics`、`claude-code`、`claude-mods`、`official` を `claude`／`anthropic` と並べた名前は `validate` がエラー。単語として `claude` 等を含むだけなら警告。
- `version` を設定するとその版に固定される。インストール済みはバージョンでキャッシュされるので、編集を反映するには版を上げて入れ直す。開発中は `--plugin-dir` で直接読む。
- 標準レイアウト（mod 以外も含む）: `skills/`、`commands/`、`agents/`、`hooks/hooks.json`、`.mcp.json`、`.lsp.json`、`output-styles/`、`workflows/`、`themes/`、`monitors/monitors.json`、`bin/`、`settings.json`。プラグイン直下の `CLAUDE.md` は読み込まれない（`validate` が警告）。
- 型定義: `--plugin-dir` の対話セッションか Claude が書いた mod では、`.claude-plugin/types/` に `claude-code/index.d.ts`（全イベントと API、各メソッドの例付き）、`claude-code-tools/index.d.ts`、`claude-code-mcp/index.d.ts`、依存プラグインごとの `index.d.ts`、`tsconfig.json` が書き出される。GitHub の `mods/types/claude-code.d.ts` は古いことがあり、食い違えば手元の版を信じる。

### register の中身（docs の例）

```javascript
let calls = 0
export function register(on) {
  on('session.start', async ($, e, next) => {
    await $.command.register({ name: 'tally', description: 'Show how many tool calls Claude has made' })
    return next(e)
  })
  on('tool.call', async ($, e, next) => { calls += 1; $.ui.invalidate('ui.render'); return next(e) })
  on('command.run', { command: 'tally' }, async () => ({ text: 'Claude has made ' + calls + ' tool calls since this mod loaded' }))
  on('ui.render', { component: 'Spinner' }, async ($, e, next) =>
    next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } }))
}
```

- `on(event, matcher?, hook)`。matcher は値、配列、正規表現のいずれか。`'classic.*'` は settings hook 全部、`'*'` は telemetry 以外の全イベント。同じイベントを matcher 無しで2回登録するとロード失敗（`is registered twice without a matcher`）。
- `on` が返す登録に `.catch(handler)`。ハンドラ内で `next.called`、`next.error.kind`（`throw`／`timeout`／`re-entry`）が読める。hook が `next` 前に失敗するとスキップされ、後に失敗すると結果は有効なまま。
- `next` の付属: `next.signal`（AbortSignal）、`next.origin`（`{ plugin, tier }`）、`next.budget`（`ms`、`remainingMs`）、`next.to(e, tier)`（`prependPlugins`／`appendPlugins` の mod のみ）。
- 実行順: sec-default と管理者の prepend の mod、ユーザーが入れた mod、管理者の `appendPlugins`、その他の組み込み mod。managed settings の `PreToolUse` は最初に走り、そのブロックは最終。他の settings hook は最後の mod の `next` の後に走る。

### 主なイベント（返せる値）

- ツール: `tool.call`（`next(e)`、`{ deny }`、`{ result }`）、`tool.check`（`{ decision: 'allow'|'ask'|'deny' }`。`e.agentId`、`e.ceiling` は v2.1.290 以降）、`tool.describe`（`{ description }`、`isDeferred`）。
- プロンプト: `prompt.submit`（`next({ ...e, text })`、`next({ ...e, context })`、`{ drop: reason }`）、`prompt.fill`、`prompt.suggest`、`prompt.edit`、`prompt.compose`、`prompt.section`、`prompt.context`、`prompt.attachment`、`prompt.mention`（v2.1.290 以降）、`skill.prompt`、`attribution.text`。
- コマンド／設定: `command.run`（`{ text }`、`{}`、`next(e)`）、`command.describe`、`config.set`、`config.describe`。
- ターン: `turn.start`、`turn.step`（async generator。`yield* next(e)`。`result.usage`、`serverToolUses` は v2.1.290 以降）、`turn.complete`（`{ text }` で答えの下に1行）。
- セッション: `session.start`（mod ごとに1回、reload 後にも。`/clear` 等では出ない）、`session.end`、`session.compact`（`{ skip }`）、`session.receive`、`session.send`、`session.append`、`session.attach`、`session.detach`、`session.measure`。
- サブエージェント: `agent.offer`、`agent.spawn`。UI: `ui.render`、`ui.resolve`、`ui.press`、`ui.input`、`ui.select`、`ui.focus`、`ui.scroll`、`ui.close`、`ui.message`、`ui.fault`（v2.1.289 以降）。他の mod: `plugin.register`（`{ refuse }`）、`engine.create`。計測: `telemetry.log`、`telemetry.mark`（`{ to: 'collector' }` の絞り込みが必須）。`classic.<Event>`（settings hook の各イベント）。mods API の各メソッドもイベント（`fs.read` など）で、`{ value }` や `{ deny }` で横取りできる。

### `$`（mods API）の namespace と戻り値

- `$.plugin`（`name`、`root`）、`$.ui`（`resolve invalidate open close panes focus scroll toast status log notice ask copy selection blit`）、`$.command`（`register run list`）、`$.tool`（`register call check list`）、`$.agent`（`register spawn list`。status は `pending running waiting idle completed failed killed`）、`$.model`（`complete fork classify`）、`$.prompt`（`submit read fill suggest compose`）、`$.turn`（`abort`）、`$.session`（`messages cwd root model turns id repo surfaces usage version compact send append authorize`）、`$.config`（`list set`）、`$.settings`（`read`）、`$.env`（`get set`）、`$.fs`（`read write list exists stat ancestors`）、`$.store`（`get set delete keys`）、`$.state`（`get set`。`atom read update derive memberOf` は `claude-code` から import）、`$.clock`（`now sleep after every`）、`$.http`（`fetch`）、`$.process`（`run spawn`）、`$.mcp`（`call connect`）、`$.audio`（`play speak`）、`$.telemetry`（`log mark`）。
- `$.command.register({ name, description, argumentHint, immediate })`: `immediate: true` で Claude の作業中にも実行できる。組み込みと同名だと throw する（`"/focus" refused: it is the built-in /focus`）。`command.run` の戻りは `{ text }`（transcript に出て Claude も読む）か `{}`（何も出さない）。
- `$.tool.register({ name, description, inputSchema })`: Claude からは `mcp__<プラグイン名>__<name>` で見える。呼び出しは同名の `tool.call` hook で処理する。`isDeferred: false` で tool search の遅延を避けられる（v2.1.293 以降）。
- `$.model.complete({ model, system, prompt, maxTokens, timeoutMs, effort })` の戻りは `{ isAnswered, text, reason, usage }`。API 失敗は reject せず `isAnswered: false` と `reason`。`prompt` を `{ text, cache: true }` のブロック配列にするとプロンプトキャッシュの breakpoint になる（v2.1.292 以降。最大4つ、TTL は 5 分で `subagentPromptCacheTtl` で 1h にできる）。Bedrock、Foundry、LLM gateway などでは `system` でなく `prompt` に置く。`$.model.fork({ prompt })` は会話ごと送る。`usage` に `cache_creation_input_tokens`／`cache_read_input_tokens`。
- `$.process.run(argv, init)` は `{ exitCode, stdout, stderr }`（シェル不使用。起動失敗とタイムアウトで reject）。`$.http.fetch(url, init)` は `{ status, ok, headers, text }`。`$.fs.list` は `{ name, kind, size, isLink }`（再帰しない）。`$.session.send({ to: { sessionId } | { agentId } })` は `{ isDelivered, reason? }`。`$.session.usage()` は `{ startedAt, context: { tokens, window, percent }, rateLimits: [{ kind, percentUsed, resetsAt }], cost }`。`$.prompt.submit({ text, asUser })`。`$.clock.every`／`after` は `cancel()` を持つタイマーを返す。`$.ui.status`／`toast`／`log` はターンを起こさずに表示する。
- hooks モジュールには Node の API も `setTimeout` も無い（`URL`、`TextEncoder`、`AbortController`、`crypto.subtle` は使える）。外との接触はすべて `$` 経由。

### 制限

- hook の実行時間は1イベントにつき 10 秒（`prompt.edit` は 50 ミリ秒。`next` と `$.clock.sleep` 以外の API 呼び出し中は数えない）、`.catch` は 1 秒。`session.end` 全体は SessionEnd hook の予算（既定 1.5 秒）。
- `$.process.run` は既定 30 秒、最大 10 分。`$.model.complete` の `maxTokens` は既定 1024、最大 64,000 またはモデルの上限。`$.fs.read`／`write` は1ファイル 4 MiB。`$.store` は合計 4 MiB の JSON。`$.session.messages()` は新しい 4,096 件。
- `drop`／`deny` の理由は 4,096 文字（超過分は切る。v2.1.292 以降。それ以前は hook が失敗）。`$.ui.invalidate` は毎秒 10 回（ターミナルの可視ペイン等は 30 回）に間引き。`$.ui.toast` は 4 秒。command／tool／subagent type／pane の名前は英数字、`_`、`-` で 64 文字まで。1ファイル内のスコープのネストは 2,000 まで。`claude plugin test` の1テストは 5 秒（`timeoutMs` で変更）。

### 描画（render site と element）

- render site（`ui.render` の `e.component`）: `Pane`、`AbovePrompt`、`UserMessage`、`AssistantMessage`、`ToolUse`／`ToolResult`／`ToolGroup`、`CommandOutput`、`AskUserQuestion`、`ToolProgress`（端末のみ）、`Spinner`、`TurnDuration`（端末のみ）、`InfoNotice`（端末のみ）、`SessionMode`、`PromptHint`。`e.surface` は `terminal` か `desktop`。
- element: `Box`、`Text`、`Button`、`Link`、`Code`、`Markdown`、`Input`、`Select`、`Client`（両方）。`Svg` は Desktop のみ（131,072 文字まで）。`Raster`（列 512、行 256 まで）と `Image`（2 MiB まで）は端末のみ。`Box` の `borderStyle` は `single double round bold singleDouble doubleSingle classic arrow dashed quote`。
- 状態の置き場所: モジュール変数（reload で消える）、`$.state`（セッション中。`/clear`、`/resume`、`/branch` でリセットされ、`ui.render` で読むと自動で再描画）、`$.store`（`~/.claude/plugins/store/` の JSON。全セッション共有で get→set は非アトミック）。

### 動作環境

- 端末（エディタ内蔵端末と JetBrains 含む）は hook も描画も可。Desktop の Code タブは hook も描画も可（端末専用 element を除く）。Desktop の WSL セッションはどちらも不可。VS Code 拡張のチャット、`claude -p`、Agent SDK は hook のみ。Remote Control は手元のセッションで hook を実行し端末に描く。クラウドセッションは、環境に届くプラグインなら hook のみ。

### 開発とテスト

- 作り方は2通り。Claude に頼む（組み込みスキル `plugin-authoring`、`/plugin-authoring`。書き込み先は `~/.claude/dev-mods/<session-id>/`、最初のファイル保存時にホットリロード可否を聞かれ、`default`／`acceptEdits` ではファイルごとに承認が要る。そのセッションだけで有効、`cleanupPeriodDays` 超過で削除）か、自分で書く。`claude -p`、`dontAsk`、信頼していないディレクトリ、`--safe-mode`／`--bare`、`disableAllHooks` では Claude が書いた mod は読み込まれない。
- `claude --plugin-dir <dir>`（保存でホットリロード。reload のたびに `register` が再実行され変数は初期化）、`/reload-plugins`、環境変数 `CLAUDE_CODE_PLUGIN_DIRS`（`:` 区切り、Windows は `;`）、`CLAUDE_CODE_PLUGIN_DIR_WATCH=1`（非対話セッションで保存時に reload）。
- `claude plugin validate <dir>`（`--strict`、`--json`）。出力の `hooks:`（イベントと絞り込み）、`calls:`（呼ぶ API）、`env reads:`／`env writes:`、`state reads:`／`state writes:`、`gating hook without .catch:` を読む。静的解析の規則: `$.ns.method` を省略せずに書く、`$` を変数に入れない・分割代入しない、`on` のイベント名は文字列リテラル、`on` を再宣言しない、import は相対パスで（例外は `claude-code`）、動的 `import()` は不可、`require` は不可。
- `claude plugin test [dir]`: `*.test.ts`／`*.test.tsx` を実行、失敗で終了コード 1。`import { expect, test, mock, tier } from 'claude-code/testing'`。`test(name, [{ plugins, timeoutMs }], async ($, on) => {...})`。テスト側の `$` は Claude Code 役で、`$.tool.call`、`$.command.run`、`$.prompt.submit`、`$.session.start`、`$.turn.complete`、`$.turn.step`、`$.classic.*`、`$.ui.mount` がイベントを発火する。`on(name, stub)` で Claude Code の返答を差し込む（API 呼び出しの stub は `{ value }`／`{ deny }`、イベントの stub はそのイベント固有の結果）。
- 組み込みモック: `mock.clock(on)`（`advance`、`set`、`now`、`settle`、`sleep`）、`mock.store(on, init)`、`mock.env(on, vars)`、`mock.session(on)`（`appended()`。v2.1.293 以降）。`$.ui.mount` のハンドルは `press`、`input`、`select`、`find`、`unmount`。`expect` は `toBe toEqual toMatch toMatchObject toContain toBeDefined toBeUndefined toThrow` と `.not`。`tier('prepend')` で policy mod をテストする。主なエラー: `no implementation for <name>`、`returned neither { value } nor { deny }`、`declares no test(): nothing ran`。stub は最初の `$` 呼び出しより前に登録する。`session.start` は自動では走らない。

### 組み込み mod（`/plugin` の Installed に Built-in として表示）

- `cc-plugin-agents-md`（AGENTS.md の読み込み）、`cc-plugin-diff`（`/diff`）、`cc-plugin-plugin-authoring`（`plugin-authoring` スキル）、`cc-plugin-sec-default`（無効化不可）、`cc-plugin-telemetry`（`DISABLE_TELEMETRY` 等で止まる）、`cc-plugin-you-should-know`（既定で無効。`/plugin enable cc-plugin-you-should-know@builtin`。長いタスク中に気づきを上に表示する副エージェント）。`disableAllHooks`、`--bare`、`--safe-mode` は組み込み mod を止めない。ソースは anthropics/claude-code の `mods/` に公開（`diff`、`agents-md`、`sec-default`、`telemetry`）。

### 無効化と管理者設定

- 無効化: 個別は `/plugin` の Installed で無効化／アンインストール。セッション単位は `--safe-mode`。常時は `~/.claude/settings.json` の `"disableAllHooks": true`（settings hook とカスタム status line も止まる。組織の管理分は動く）。`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` は早期アクセス用で、v2.1.287 以降は無視される（`0` でも mod はオフにならない）。
- 管理者: `pluginConfigs["cc-plugin-sec-default@builtin"].options` の `allowManagedModsOnly`（ユーザーの mod を全て拒否。組織の mod と組み込みは動く）、`allowModsToOverrideDenyRules`（ユーザーの mod が `deny` ルールを上書きして承認できる）。ほかに `allowManagedHooksOnly`、`disableAllHooks`、`disableSideloadFlags`（`--plugin-dir` と `--plugin-url` を拒否し、セッション中に Claude が書く mod も止める）、`prependPlugins`／`appendPlugins`（`acme-guard@acme-tools` のような id）。
- guard は managed settings のある端末か、Team／Enterprise でサインインしたユーザーに読み込まれる。guard は管理 hook、システムプロンプト、管理 `CLAUDE.md`、管理 MCP を守る。ユーザーの mod は `deny` ルールと管理 `PreToolUse` のブロックは覆せないが、`ask` ルールや管理外の `PreToolUse` のブロックは覆せる。mod 自身の `$.fs`／`$.process` 呼び出しは `Read(.env)` の deny の対象外。
- 「組織の mod」と見なす条件: managed `enabledPlugins` が `true`、managed settings がそのマーケットプレイスをユーザー端末上のディレクトリ（絶対パス）で指す、マーケットプレイスが相対パスでそのプラグインを列挙する。GitHub／git／URL／npm 由来はキャッシュにコピーされるのでユーザーの mod 扱い。`plugin.register` の hook で他の mod を `{ refuse }` できる。
- 導入前の確認: `claude plugin validate ./some-mod` の `hooks:`／`calls:` を見る。

### 配布と公開の手順

- インストール: `/plugin install <plugin>@<marketplace>` または `claude plugin install <plugin>@<marketplace>`。シェルで入れたら開いているセッションで `/reload-plugins`。
- 共有の選択肢（create ページ）: 少人数にはディレクトリか `.zip`、チームには自前のマーケットプレイス（リポジトリの設定で全員に登録可）、組織全体には管理者が managed settings で配る、一般には公開リポジトリのマーケットプレイスか Anthropic のディレクトリへの申請。
- リリース: `plugin.json` の `version` を上げて push。`claude plugin tag`（`{name}--v{version}` のタグ。`--push` で origin へ）は他のプラグインが版の範囲で依存するときに使う。公開済みの `name` は変えない（変えると既存ユーザーが失う。マーケットプレイスの `renames` で移行）。依存は `dependencies` に書く。
- Anthropic のディレクトリへの申請手順（publish ページ）: (1) 有料の claude.ai プランが必要（Pro／Max は自分のアカウント、Team／Enterprise は Owner。Enterprise は Owner がカスタムロールで **Directory** 権限を委譲できる）。(2) `claude plugin validate ./your-plugin --strict` をローカルで通す（ポータルには CLI が見ない追加規則がある）。(3) 構成要素のうち Claude Code 専用で claude.ai／Cowork では読み込まれないものを確認する。(4) claude.ai/directory/manage の開発者ポータルから申請する。`claude-plugins-official` は申請を受け付けず、Anthropic のパートナー窓口経由。審査の詳細は claude.com 側（本ページの範囲外）。ディレクトリ経由で入れたプラグインは Claude Code では `<name>@synced` として読み込まれる。ディレクトリ掲載用に `plugin.json` で `icon`（プラグイン内の画像パス）と4つの URL（`documentationUrl`、`supportUrl`、`privacyPolicyUrl`、`termsOfServiceUrl`、`https://`）を使い、マーケットプレイスのエントリには書かない。
- サンプル: anthropics/claude-code-playground の `claude-code/mods` の `token-weather`、`blast-radius`、`replay-theater`（無保証）。clone して `--plugin-dir` で試すか、`claude-code/mods` をマーケットプレイスとして追加し `claude-code-playground-mods` から入れる。
