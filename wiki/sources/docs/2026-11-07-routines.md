# Automate work with scheduled tasks（2026-11-07 再取得・名称と提供範囲のみ）

## 要点

- ページ名と本文の呼称は **scheduled tasks**（原文: "scheduled tasks, formerly routines"）。旧称 routines は一部に残る、と専用の節で説明している。
- 段階は **research preview**（"Behavior, limits, and the API surface may change"）。
- 提供プランは **Pro、Max、Ultra、Team、Enterprise**。作成と管理は claude.ai/code/routines か CLI の `/schedule`。
- `/schedule` の別名として `/routines` が残る。
- Team／Enterprise の Owner は「**Scheduled tasks (Was Routines)**」または「**Routines**」のトグルで組織全体を無効にできる。Enterprise のカスタムロールでは scheduled tasks の権限も必要。
- ローカルで動かす別機能として Desktop scheduled tasks と `/loop` がある。

## 具体的な値

- 旧称が残る場所（原文の節 "Where the name routines still appears"）: アプリ（サイドバー、**New routine** ボタン）、URL `claude.ai/code/routines`、CLI の `/routines` と説明文、API の `/fire` のパス、beta ヘッダー `experimental-cc-routine-2026-04-01`、response の `type`、`<routine-fire-payload>` タグ、組織設定のトグル。
- `/schedule` の使い方の例: `/schedule daily PR review at 9am`、`/schedule tomorrow at 9am, summarize yesterday's merged PRs`。GitHub トリガーの追加は CLI で v2.1.225 以降。
- 1 時間あたりの上限（表）: スケジュール実行（1 回きりを含む）は 100 回／アカウント。Run now、API fire、1 回きりの再設定は 30 回／タスク（3 つで共有）。Run now と 1 回きりの再設定は 100 回／アカウント。GitHub イベントにも単位ごとの上限があり、超過分は破棄。
