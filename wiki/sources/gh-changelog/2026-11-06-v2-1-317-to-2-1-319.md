# CHANGELOG.md 2.1.317〜2.1.319

公開日時（npm の time を JST に換算）: 2.1.317 は 2026-11-03 08:57、2.1.318 は 11-04 06:55、2.1.319 は 11-06 09:58。

## 要点

- **auto mode の変更（2.1.319）**: テレメトリや feature flag がオフ（LLM ゲートウェイ経由を含む）のとき、サーバーが確認できない呼び出しは「尋ねる」か「拒否」になり、組み込み分類器へのフォールバックは無くなった。従来動作に戻すには `CLAUDE_CODE_AUTO_MODE_SERVER=0`（Bedrock、Vertex、Foundry は変更なし）。`claude -p` は、安全判定が得られずアクションが拒否された場合に exit 1 になる。
- **権限・安全**: `permissions.denyInsteadOfPrompting`（権限プロンプトで待つ呼び出しを拒否して続行、2.1.319）。Bash 権限のバイパス（環境変数プレフィックスでコマンドの一部を隠せる）、worktree 作成時のサンドボックス脱出、`sed` の権限チェック漏れ、`/rewind` の symlink 経由の復元・削除を修正（2.1.319）。アカウントのメールアドレスをネットワークへ送る web／シェルのツール呼び出しの前に確認を求める（2.1.317）。
- **MCP tasks をターミナルでサポート（2.1.319）**: MCP サーバーがタスクとして実行するツール呼び出しは即バックグラウンドへ移る。feature-flag 取得なしでも動く。
- **Claude apps gateway**: コストレポート API `GET /v1/organizations/analytics/cost` と IdP グループの日次記録（2.1.317）、`admin.pooled_conflict_rule`／`admin.pooled_priority_order`、`login_notice`、`CLAUDE_GATEWAY_LOG_FORMAT=json`（2.1.319）、mantle upstream の `assume_role`（2.1.318）。
- **設定ファイルと認証の堅牢化（2.1.318）**: 共有ネットワークホームでの `~/.claude.json`、設定、保存済みログインの破損・消失対策を多数。claude.ai ログインの失効日を `claude auth status` に表示。
- 修正は大量（各版 数十件）。主なものだけ下に記す。

## 具体的な値

### 2.1.319
- 変更 auto mode（テレメトリ／feature flag オフ、ゲートウェイ経由含む）: サーバーが確認できない呼び出しは尋ねるか拒否。組み込み分類器へのフォールバックなし。維持するには `CLAUDE_CODE_AUTO_MODE_SERVER=0`
- 変更 auto mode（ゲートウェイ経由）: `CLAUDE_CODE_AUTO_MODE_SERVER=1` は `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` が設定されていてもサーバー側チェックをオンにする。managed settings が後者を設定する場合は `1` も設定する必要あり
- 変更 auto mode: プロジェクトの settings ファイルやプラグインは、プロジェクト外でオフにしたサーバー側チェックを再びオンにできない
- 修正: managed settings の `CLAUDE_CODE_AUTO_MODE_SERVER=1` が、ゲートウェイの URL がそこだけに設定され server-managed settings が取得できないとき無視される問題。`/status` が "Auto mode server: Enabled" と誤表示する問題。`claude -p` が安全判定なしで拒否されても exit 0 になる問題（text／JSON で exit 1 に）。permission rules／`autoMode` 設定が非常に大きいとき理由なしで拒否される問題（`autoMode` の deny ルールが無ければ terminal で尋ねる）
- 追加 `permissions.denyInsteadOfPrompting`: 権限プロンプトで待つ呼び出しを拒否してターンを続行（terminal、subagents、teammates）
- 追加 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`: MCP タスクをバックグラウンドへ移さず、ツール呼び出しの中で待つ
- 変更 MCP tasks は feature-flag 取得なし（Bedrock、Vertex、Foundry、LLM ゲートウェイ、`DISABLE_TELEMETRY`）でもターミナルで動く。オフにするのは `CLAUDE_CODE_DISABLE_MCP_TASKS=1`
- 追加 `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`: テレメトリをオフにせず feature-flag の取得だけ止める（全 flag が組み込み既定値）
- 追加 `/claude-api latency-optimize`: API コードの待ち時間の所在を探し、eval に対して高速な設定を試す
- 追加 `/usage`: 支出上限のない gateway 開発者向けに今日・今週・今月の支出（gateway が当版以降のとき）
- 追加 `/tasks` の "Earlier in this session" 行（終了済みサブエージェントを再度開いてメッセージ可能）
- 追加 `ant auth login` のサインインで Claude Console 組織に課金される場合の警告と、起動時の課金先組織名の表示
- 追加（Claude apps gateway）: `admin.pooled_conflict_rule`、`admin.pooled_priority_order`（複数グループ所属時にどのプール予算を先に使うか）、任意の `login_notice`、`CLAUDE_GATEWAY_LOG_FORMAT=json`（`severity`、`time`、`message`）、`desktopHome` 無しで `coworkTabEnabled: false` や `chatSessionRetentionDays` に頼るポリシーへの起動警告（Claude Desktop の November 10 の変更に先立つ）、Bedrock guardrail をヘッダーで指定する managed settings への警告、AWS GovCloud と他 upstream の混在への警告。支出上限エラーは "spend limit reached · resets Dec 1"、続いて `admin.blocked_message`
- 変更: `CLAUDE_CODE_PROXY_RESOLVES_HOSTS` は settings ファイルから設定不可（ホストがネットワークを管理する場合。プロセス環境で設定）
- 変更: `ALL_PROXY` だけが設定されているとき、TLS 検査プロキシ向けの自動証明書修復は走らない（`HTTPS_PROXY` に http:// URL を設定）
- 変更: 自己ペースの `/loop` は、再スケジュールなしでターンが終わると終了。従来動作は `CLAUDE_CODE_LOOP_KEEPALIVE=1`
- 変更: PostToolUse hook は、新しいメッセージでターンが中断された後に終わるツール呼び出しでも、最大10秒で実行
- 変更: Monitor の WebSocket watch はすべての Bash コマンドのルールに従う（deny は拒否、ask ルール下では Monitor の allow・bypass・auto mode でもプロンプトを飛ばさない）。セッションの exact な Bash／PowerShell ask ルールは、広い deny ルールがコマンドを覆うなら尋ねず拒否。`which` はフラグ付きだと許可を求める
- 変更: `--add-dir` ディレクトリはそのディレクトリ自身の trust dialog を受け入れた後にだけ plugin marketplace を登録。Bash サンドボックスがオンのとき、起動フォルダ配下の `.claude/skills` は、そこで起動するか `/cd` したときだけ読み込む
- 修正（セキュリティ）: Bash の deny／ask ルールが引用符付きの語で書かれたコマンドを見逃す問題、環境変数プレフィックスによる権限チェックの回避、worktree 作成時のサンドボックス脱出、`sed` が accept-edits／auto mode で権限チェックを飛ばす問題、`/rewind` が directory symlink 経由でファイルを復元・削除する問題、claude.ai コネクタの端末名（`mcp__claude_ai_Slack`）で書いた deny／ask ルール・hook matcher・`disallowedTools` が Claude Desktop で無視される問題（Desktop が当版を含んで以降）
- 修正: 自己ホスト runner の `--trust-workspace false` がリポジトリ設定の hook と skills も止める
- 変更: cloud sessions はセッション限定の allow ルールを、deny／ask ルールを全て保てない worker 移動時に落とす（再度尋ねられうる）
- 変更: Claude in Chrome の `shortcuts_list`、`shortcuts_execute` を削除
- 変更（self-hosted runner）: `CLAUDE_RUNNER_CHECKOUT_PATH` はリポジトリごとにフォルダ（重複は `-2`、`-3`）。セッション終了時のデバッグログのアップロードを廃止（`--remove-session-state` を付けない限り失敗セッションのログは runner ホストに残る）
- [Cloud sessions]、[VSCode]、[Code Review]、[Claude Tag] の修正・追加が約30件（Claude Tag の Models admin ページ行、Code Review の組織リンク解除時の All repositories オフ、VS Code の 50,000 文字超プロンプトの扱い ほか）
- その他の修正・改善が約75件

### 2.1.318
- 追加（gateway）: `mantle` upstream の `assume_role`（別 AWS アカウントのロール、開発者別の AWS コスト按分）
- 追加: mod の `$.model.fork` に `effort` オプション（`low` 等）。claude.ai ログインの失効日を `claude auth status` の `loginExpiresAt` と `claude -p` JSON の `credential_expires_at` に表示。失効10日前から `claude -p` の text 出力に stderr 警告。mods を有効にする問いへの回答を記録
- 修正（リグレッション）: `--continue` が、不正なツール呼び出しの再試行が尽きた後に以前の会話を失うことがある（2.1.314 で発生）
- 修正: macOS で多数の Bash コマンド実行中にメモリが増えて停滞する問題。権限プロンプトが、メッセージ送信直後に打ったキーで答えられる問題
- 修正（設定・ログインの堅牢化）: 共有ネットワークホームで `/logout`、`claude auth logout`、`claude mcp remove` が失敗しても成功と表示される問題、`claude mcp add`／`remove` がロック無しで書く問題、`claude plugin` が slow token refresh の保存前に終了してサインアウトされうる問題、`~/.claude.json` が不正 JSON のとき非対話起動が既定値で置き換える問題（失敗して復元方法を示す、anthropics/claude-code#87551）、空の `~/.claude.json` を破損と誤報する問題、`allowedProviders` が同じマシンの別ログインのものでセッションを拒否する問題、`NODE_EXTRA_CA_CERTS` が空・非 PEM・先頭が壊れた証明書だと全接続が失敗する問題（読める証明書を使い stderr に警告）、`forceLoginOrgUUID` のマシンで許可組織の `setup-token` のトークンが拒否される問題
- 修正: アイドル時 compaction が要約でない返答で会話を置き換える問題。`claude remote-control` ホスト、バックグラウンド daemon、self-hosted runner が、更新やバージョン掃除でバイナリが消えた後 `spawn ENOENT` で起動できない問題。別ユーザー（`sudo claude` 等）の実行中プロセスのバイナリをバージョン掃除が消しうる問題
- 修正（Cloud sessions）: 再起動後に承認済みシェルコマンドがセッション開始フォルダで動く問題（入れない場合は実行しない）、`Setup` hook が `CLAUDE_ENV_FILE` に書いた変数が Bash に届かない問題、アップロード拒否が数分続くとターン途中で停止する問題、`gh run view --log` と `gh api` のログ取得
- 変更: IDE ターミナルで起動したとき IDE 拡張を自動でインストール・更新しない（`/ide` か拡張ビューを使う）
- 変更: "Switch models when a message is flagged" が "Ask each time" のとき、サブエージェントはモデルを切り替えず停止。バックグラウンドのサブエージェントは全プロバイダで、シェルコマンドを3分後にバックグラウンドへ移す（プロンプトキャッシュの期限切れ防止）。Bedrock、Vertex、Foundry、テレメトリオフでは、サブエージェントの進捗要約が冷えたキャッシュで最大5分待つことがある
- 変更: mod が `prompt.submit` で添付する内容は system message ではなくユーザーのターンに残る
- 変更: `deniedMcpServers` の URL エントリは、upstream URL が一致する Anthropic 提供サーバーと、cloud sessions・self-hosted runner のコネクタもブロック（それ以外はコネクタを名前で deny）
- 変更: `/claude-api managed-agents-onboard` は新しい agent の組み込みツールと quickstart の MCP ツールに既定で `auto` 権限ポリシー（"Judge risky actions"）を与える（"run without asking" で解除）
- 変更: `/permissions` のルール詳細などを標準 dialog に（Ctrl+C 2回で戻る／キャンセル）
- 削除: 2.1.288 の、2.1.286 以前で始めた会話を再開する際に以前の thinking を保つ修正（thinking は落とされうる）
- 変更（self-hosted runner）: orchestrator のログ行 `ok session=…` は全ログレベルで stdout に出て `reason=…` が `jti=…` の後に付く。`nack session=…` は `retryable=…` の後に `reason=…`。`retryable=true:`／`retryable=false:` に一致するスクリプトは要更新。追加 `CLAUDE_RUNNER_SPAWN_REASON`（`runner_lost`、`resumed` 等）
- 追加（Cloud sessions）: No repository オプション（Anthropic-hosted 環境でリポジトリ無しで開始）、`google-chrome` と `CHROME_PATH` での組み込み Chromium
- その他の修正・改善が約40件

### 2.1.317
- 追加: アカウントのメールアドレスをネットワークに送る web／シェルのツール呼び出しの前に確認
- 追加: Agent SDK の hook callback に `onFailure: "block"`（callback の失敗でアクションをブロック）
- 追加: OTel のメトリクス、イベント、span に `anthropic.plan`、`anthropic.seat_type`、`anthropic.provider`、`anthropic.custom_base_url`
- 追加（gateway）: 管理 API のコストレポート `GET /v1/organizations/analytics/cost`（期間内の過去支出を合計・開発者別・日別・IdP グループ別）。`admin:` を設定した gateway は各開発者の IdP グループを `admin.identity_retention_days` の期間、日次で記録（コストレポートがグループ別集計に使う）
- 追加 `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID`: self-hosted runner で `1` にすると、セッション内の `claude -p` がそのセッションの ID と transcript を使う（以前の版の動作）。修正として、セッション内の `claude -p` が既定ではセッション ID を共有して transcript に書いていた問題（その版では別 ID に）
- 追加: Claude Desktop の Code タブで、組織のリモート managed settings が未読込のときと読込後の通知。auto mode のチェックがサブエージェントのツール呼び出しに答えなかったときの通知。`/schedule` に、頼んでいないコネクタが付いた場合の警告
- 修正: LLM ゲートウェイが server-side safety check に 403 や 422 を返すと auto mode が毎ターン失敗する問題（apiKeyHelper 付き 403 は従来どおり）。`claude -p` が満杯ディスクや quota で transcript／`~/.claude.json` の書き込みを失っても exit 0 になる問題（text／json で exit 1）。クラウド内 auto mode で Artifact ツールのアップロード等が承認待ちになる問題
- 修正: 一部の TLS 検査プロキシで root 証明書更新後に "unable to get local issuer certificate" になる問題。OTel のエクスポートが、https:// エンドポイントへのプロキシ経由で詰まる問題、応答しないプロキシで固まる問題（10秒でタイムアウト、`OTEL_EXPORTER_OTLP_TIMEOUT` で最大30秒）。stdio MCP サーバーが、env 設定が空だと空の `AWS_BEARER_TOKEN_BEDROCK` を受け取る問題（unset に）。`DISABLE_PROMPT_CACHING_OPUS`、`DISABLE_PROMPT_CACHING_SONNET` が `[1m]`、他リージョン、日付なしの既定モデル表記に効かない問題。PDF のメタデータでページ数を過少に数える問題。Grep と Glob が時間切れの部分結果を完全とみなす問題
- 変更: SendMessage は実行中のバックグラウンドエージェントへのメッセージを、実行中のコマンドを止めずにバックグラウンドへ移して早く届ける。メインと異なるモデルのサブエージェントとチームメイトは、セッションの effort ではなくそのモデルの保存済み effort か既定を使う
- 削除: Read ツールの "file unchanged since your last Read" スタブ（未変更のファイルを再読すると内容を返す）
- 変更: 組み込み `plugin-authoring` スキルが、mod が動いた後に共有の手伝いを一度申し出る。終了時の "Background work is running" プロンプトをプラグイン monitors では省略
- 修正（Windows）: 一部ボリュームでネイティブパス検索が失敗し全ツール呼び出しが拒否される問題（フォルダの identity で比較）。scratchpad 等の一時パスがプロジェクトのパス長に比例して伸び、260 文字制限に当たる問題
- 修正（gateway）: グループのプール予算が尽きたとき、ステータスラインと `/usage` が開発者自身の上限を 100% 使用と表示する問題。Bedrock の "Input is too long." を隠し、compaction せず "upstream rejected the request" で毎ターン失敗する問題
- [VSCode]（fork が会話を落とす問題、`ultrathink` がテレメトリオフで effort を上げない問題 ほか）、[Cloud sessions]（MCP サーバーが求めるリンクのカード、network secret の上書き防止、新規 scheduled task が組織の既定環境を使う）、[Remote Control]、[Claude Tag] の修正が約15件
- その他の修正・改善が約50件
