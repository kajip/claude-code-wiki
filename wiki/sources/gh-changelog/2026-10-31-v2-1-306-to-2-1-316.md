# CHANGELOG.md 2.1.306〜2.1.316

公開日時（npm の time を JST に換算）: 2.1.306 は 2026-10-21 11:28、2.1.307 は 10-22 05:47、2.1.308 は 10-22 13:19、2.1.309 は 10-23 05:34、2.1.310 は 10-24 06:20、2.1.311 は 10-27 04:47、2.1.312 は 10-28 03:36、2.1.314 は 10-30 09:12、2.1.315 は 10-31 06:05（npm のみ）、2.1.316 は 10-31 09:42。2.1.313 は npm に無く、CHANGELOG にも項が無い。

## 要点

- **Opus 4.8 の fast mode を非推奨にした（2.1.316）**。2026-10-30 付けで非推奨、2026-11-30 に削除。削除後は Opus 4.8 の fast mode リクエストはエラーになり、標準の Opus 4.8 へはフォールバックしない。Opus 5.5 への移行を勧めている。
- **effort 関連**: `CLAUDE_CODE_SUBAGENT_EFFORT`（他に指定が無いときのサブエージェントの effort）と `CLAUDE_CODE_DISABLE_ULTRATHINK`（2.1.316）。`ultrathink` は Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1（Anthropic の API 経由）で xhigh effort のターンになる（2.1.311、VS Code は 2.1.316）。
- **権限・サンドボックスの強化**: `permissions.blockWritesOutsideWorkingDirectories`（2.1.314）、Desktop／VS Code の bypass permissions mode で危険な `rm`／`rmdir` を即時拒否（2.1.309）、`sed -i` を通常の Bash 扱いに（2.1.309）、サンドボックスの回避につながる修正が 2.1.309 に多数（下記）。
- **Claude apps gateway**: 共有の月間予算 `pooled_budget`、`managed.policy_mode: layered`、`guardrail.input_tagging`、`guardrail_trace`、upstream の `groups`、`oidc.user_id_claim`。
- **Managed Agents**: `/claude-api` スキルが subagent チームを `multiagent_20261001`（dynamic workflows 既定オン）で作る方式に変わった（`coordinator` をやめる、2.1.309）。`/claude-api managed-agents-secure` 等が続く。
- **コンパクション**: VS Code と Claude Desktop の Code タブにアイドル時 compaction（2.1.314）。Bedrock／Vertex／Foundry／ゲートウェイでも 1 時間プロンプトキャッシュ有効時は動く。
- 修正は大量（各版 数十件）。主なものだけ下に記す。

## 具体的な値

### 2.1.316
- 追加 `CLAUDE_CODE_DISABLE_ULTRATHINK`: `ultrathink` キーワードをオフにする
- 追加 `CLAUDE_CODE_SUBAGENT_EFFORT`: 他に指定が無いとき、セッションの effort を継承せずにサブエージェントが動く effort を決める
- 追加 `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`: 互いに認証し合うループ状のシステム相互証明書を残す（私設 CA が必要とするサーバー向け）
- 追加（Claude apps gateway）: `pooled_budget`（spend limits の admin API。グループのメンバーが共有する月間予算。各メンバーの上限に加えて掛かる）、`managed.policy_mode: layered`（一致する全ポリシーを、下に挙げたものの上に重ねてマージ。従来は最初の1つだけ）、Bedrock の upstream に `guardrail.input_tagging`（Bedrock guardrail の prompt attacks フィルターが要る入力タグでプロンプトを包む。`all_messages_and_system` はシステムプロンプトにもタグを付ける）
- 非推奨: Opus 4.8 の fast mode（2026-10-30 付け、削除は 2026-11-30。削除後はエラーでフォールバックしない。Opus 5.5 への移行を推奨）
- 修正（gateway）: 要求が名指しする全モデルを `availableModels`、`deniedModels`、`models` と照合していなかった問題。ブロックされたモデルは、フィールド名つきの 400 を返す
- 修正: `--restricted` セッションが、Read の allow ルールが覆う作業ディレクトリ外のファイルをアップロードする問題
- 修正: 管理側の `autoMode.allow` が `"$defaults"` を含まないとき、ホストアプリの `--settings`、`/permissions` の最初のルール、`/auto-mode-setup` によって組み込みの例外が戻る問題。変更: `"$defaults"` を含まない `autoMode.allow` でも、スケジュールタスクのプロンプトの組み込みルールは外れない
- 修正: auto mode が安全判定の返答なしでターンを止めたとき、cloud session／cloud scheduled task が失敗扱いにならない問題。`CLAUDE_CODE_AUTO_MODE_SERVER=1` がホストアプリ（Claude Desktop 等）のプロキシ／ゲートウェイ配下で無視される問題
- 修正: `sonnet`、`opus`、`haiku` が Vertex／Bedrock で、最新が使えないとき古いモデルに切り替わらずエラーになる問題。サブエージェントが親サブエージェントのモデルを継承していたのに、バックグラウンドの起床でメインのモデルへ移る問題
- 変更（server-managed settings、Team／Enterprise ログイン）: Anthropic の API から取得した設定は承認プロンプトなしで適用。検証に通らない保存コピーは拒否
- 変更: `/code-review`（Desktop の Code タブとウェブ）の cloud／`claude remote-control` セッションで findings カードを表示
- [VSCode] Claude apps gateway へのサインインをチャットパネルから可能に。`ultrathink` は xhigh effort で実行され、チャットボックスで虹色に。`[1m]` タグ付きモデル（`opus[1m]` 等）で Effort スライダー、Ultracode スイッチ、モデル名が消える問題を修正
- [Cloud sessions] MCP サーバーが求めるフォームのカード、"Catching up…" 行を追加。network secrets を Enterprise メンバーが自分の cloud environment で追加・削除できるように変更
- [Claude Tag] Respond automatically スイッチを "How Claude participates" の選択に変更。Slack Connect、canvas、live status checklist などの修正
- [Code Review] 分析ページに findings-by-severity カード
- その他に、シェルの残留プロセス、bash エイリアス、PowerShell hook の exit code 2、SSL 証明書エラーの説明、`/diff` の高速化などの修正・改善が約25件

- 修正: PreCompact hook の出力が非常に大きいと compaction が失敗・反復する問題（各 hook の出力は 10,000 文字で切る）
- 変更: 自分の設定ファイルと同様、組織の server-managed settings のローカルコピーの編集前に確認を求める。`/ultrareview` が git を走らせる前に workspace trust を確認。フラグが付いた要求は、`ANTHROPIC_DEFAULT_OPUS_MODEL`、`availableModels`、`deniedModels` が古い Opus しか（または何も）残さないとき、拒否で終わらず別モデルで再試行する。hook の `if` 条件 `Monitor(tail *)` が Monitor ツールのシェルコマンドに `Bash(tail *)` と同様に一致。`FORCE_HYPERLINK=false`（`no`、`off` も）はハイパーリンクをオフにする（以前はオン）。Cowork cloud sessions の auto mode では、MCP ツール呼び出しへの hook の allow を「答えなし」とみなし、分類器か権限プロンプトが決める
- 修正: `~/.claude/skills/.trash` と `~/.claude/plugins/.trash` が際限なく増える問題（それぞれ約 1024 件に制限。`cleanupPeriodDays` に関係なく）
- 改善: auto mode のブロックメッセージ（コマンド名、再試行可、`/permissions` で確認）、`/permissions` の review タブを Recently blocked に改称、サブエージェント多数の headless／SDK のメモリ使用量

- [VSCode] `CLAUDE_CODE_DISABLE_CFC_PROMPT` が、拡張が Claude in Chrome の指示をメッセージに足すことも止める（ブラウザツールは使える）ほか修正
- [Cloud sessions] 完了済みの一回限りタスクを表示する Include completed ボタン、スケジュールタスクが claude.ai のアカウントで有効なプラグインを読み込む、セットアップスクリプトがエラー終了しても web／デスクトップ／モバイルから起動する、ほか修正

- 変更: モデル名と ID から、効果の無いモデルの `[1m]` 接尾辞とラベルを外す（接尾辞は引き続き受け付ける）
- 変更: Bedrock、Mantle、Vertex、Foundry で、モデル設定を downloads.claude.ai の署名付きファイルから読み込む。止めるには `CLAUDE_CODE_MODEL_CATALOG=off`
- 変更: `DISABLE_COMPACT` は settings ファイルと mod の `$.env.set` では compaction をオフにする方向にしか効かない（オンに戻せない）。`CLAUDE_CODE_SYNC_SKILLS` を設定し feature-flag 取得がオフのセッションは、同じマシンの他のセッションが取得した最大 10 分前の claude.ai skills 一覧を再利用
- 変更: `--output-format json`／`stream-json` は、文字列内の DEL、C1 制御、Unicode format 文字を `\uXXXX` でエスケープ。`claude purge` は「このコンピューター上のデータだけを消す」と表示。`/code-review` は effort を先頭に置き、max は求められたときだけ
- 修正: 標準コンテキストのセッションが 200K トークン超で "Usage credits required for 1M context" で止まる問題（compact して続行）。`SubagentStop` hook が実行中のサブエージェントごとに毎分約2回走る問題。サブエージェントの分離 worktree が、起動した background subagent の作業中に消える問題。agent teams の task list が `--resume` 等で空になる問題
- 修正: Claude Code が API が再試行不可とした要求を再試行し、無人リトライモード（`CLAUDE_CODE_RETRY_WATCHDOG`）で無期限に続きうる問題
- 修正（Linux）: `--plugin-dir` が追加ディレクトリでもあり `permissions.blockReadsOutsideWorkingDirectories` がオンのとき、サンドボックスの Bash が `bwrap: Can't create file` で失敗する問題
- 改善: compaction（返答に要約が無いとき、置き換える前にもう一度要約を求める）、Pro／Max の起動時間（1 時間以内の起動で2つのネットワーク要求を省略）、`/teleport` が compaction 済み cloud session の読み込みを警告
- [VSCode] コードブロックのシンタックス色、`DISABLE_TELEMETRY` を VS Code のテレメトリ設定がオフのときに付けて起動。[Claude Tag] analytics に Skills ビュー。[Code Review] 一時的なサーバー障害で起動に失敗したレビューを1回自動再試行
- その他の修正・改善が約55件

### 2.1.309
- 修正（サンドボックス・権限）: サンドボックスの Bash が各コマンドの前にシェルの startup ファイルをサンドボックス外で実行する問題。macOS の `denyWrite` グロブが symlink 経由のとき実位置で効かない問題。サンドボックス化コマンドや自動承認の編集が `--mcp-config` で渡した MCP 設定ファイルを変更できる問題。無効な MCP サーバーが print／SDK セッションの後続の権限プロンプトで再接続する問題。リダイレクトが開けず失敗しうるコマンドが設定した変数を Bash 権限チェックが信用する問題。`cd` が包まれ／前置された git の複合コマンドで権限チェックが出ない問題。`Edit(path)` の deny ルールが、subshell を含む Bash のリダイレクトを止めない問題。worktree 分離セッションが、locale 前置コマンドや zsh の算術コマンドの一部を受け入れる問題。worktree とブランチ checkout が git replace refs を無視するように。profile store の書き込み保護が symlink 経由の config ディレクトリで効かない問題。Linux でバックグラウンドコマンドがセッションより長生きするとサンドボックスの書き込み拒否が外れる問題
- 修正（Windows）: PowerShell の権限チェックが、現在ディレクトリを対象とし余分な引数を持つ `Set-Location`／`cd` を自動承認する問題（現在は確認する）。PowerShell hook の exit code 2 でブロックされない問題
- 変更: `sed -i` は標準の Bash プロンプトを出し、書いたとおりに実行する（模擬の編集プレビューをやめる）。他の Bash 編集と同様、`/rewind` では戻らない
- 変更: Desktop アプリと VS Code の bypass permissions mode で、危険な `rm`／`rmdir` のプロンプトを、書き換えヒントつきの**即時拒否**に変更（無人セッションを止めないため）
- 変更: 設定でサンドボックスから除外したコマンドは、サンドボックスが有効だが動かせないとき、その write-list のパスへの書き込み前に確認する（サンドボックス外のフォールバックは拒否）
- 変更: `claude ultrareview` は workspace trust を要する（ターミナルでは確認、それ以外では拒否）。スクリプトは `--trust-workspace`（値なし）か `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`
- 変更: worktree の作成・再利用で git が on-demand にオブジェクトを fetch しない（partial clone では先に fetch）
- 変更: `/claude-api` スキルは Managed Agents の subagent チームを `multiagent_20261001`（dynamic workflows 既定オン）で作る。以前は `coordinator`
- 修正・改善（`/claude-api`）: `ant beta:worker poll --on-work` が trace context を渡すという誤り、C# の tracing、Claude Platform on AWS の API span の記述。API tracing を SDK tracing と並べて提案。未対応と言う前にライブ docs を確認。サービスアカウントキーと Workload Identity Federation トークンが OpenTelemetry の送信先を管理できる
- 修正: Claude が PR／issue／コメントでロール名やプレースホルダーを mention として書き、無関係な GitHub ユーザーに通知が飛ぶ問題
- その他の修正・改善が約40件
