# CHANGELOG.md 2.1.303〜2.1.305

公開日時（npm の time を JST に換算）: 2.1.305 は 2026-10-21 04:29、2.1.304 は 2026-10-20 04:47、2.1.303 は 2026-10-19 06:15。

## 要点

- **2.1.305 のセキュリティ上重要な追加**: `sandbox.allowNestedUserNamespaces`。Linux のサンドボックス内コマンドがユーザー名前空間を作れるようになる（Chromium、rootless podman 向け）が、CHANGELOG は「サンドボックスのファイル保護を回避しうる」と明記している。
- **2.1.305 の挙動変更**: `allowedMcpServers` が、`managed-mcp.json` の stdio サーバーのうち `${VAR}` を `env` にだけ使うものを絞り込まなくなった。allowlist から漏れていたサーバーが、アップグレードで読み込まれるようになる。止めるには `deniedMcpServers` を使う。
- 2.1.304 はほぼ mods の API 拡張（`decider: "person"`、`e.isReadOnly`、`settings.read` の変更）、`/auto-mode-setup` の対象拡大、Code Review の review levels、tool search の既定化（カスタム `ANTHROPIC_BASE_URL`）、skill hooks の上限。
- 2.1.303 は「Bug fixes and reliability improvements」のみ。
- 2.1.304 でカスタム `ANTHROPIC_BASE_URL` 配下の tool search を既定オンにした結果、ゲートウェイが拒否すると全リクエストが失敗する回帰が出て、2.1.305 で再試行（tool search 抜き）により修正。
- 修正は大量（2.1.304 で約60件、2.1.305 で約40件）。主なものだけ下に記す。

## 具体的な値

### 2.1.305
- 追加 `sandbox.allowNestedUserNamespaces`（Linux。Chromium、rootless podman 向け。ファイル保護を回避しうる）
- 追加 `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS`: 無人リトライモード（`CLAUDE_CODE_RETRY_WATCHDOG`）が、リセット前に解除された利用上限に気づくようにする
- 変更 `allowedMcpServers`: `managed-mcp.json` の stdio サーバーで `${VAR}` を `env` だけに使うものは絞り込み対象外。allowlist 漏れのサーバーはアップグレードで読み込まれる。外すには `deniedMcpServers`
- 変更: Claude Desktop がパスでマウントしたプラグインは、組織の managed 設定が `allowManagedPermissionRulesOnly` のとき `allowed-tools` を保持しない
- 変更: `/artifacts` の削除確認は 1 または Enter で保持、2 で削除、Esc で取消。`y`／`n` は不可（2.1.304 では y、n も可だった）
- 変更: mod のドック領域は端末幅の 45% 以内
- 改善: `/usage` の警告が「出典を示す1行の修正案」になり、`f` で適用。VS Code と `/doctor` にも同じ修正案。MCP の同意ダイアログで Enter の誤承認が起きにくく。mod の `Image` が iTerm2 3.5 以降（fullscreen rendering）で画像を描く
- 修正（回帰）: Vertex、Bedrock などでエンドポイントやゲートウェイが tool search を拒否すると全リクエストが失敗する問題（2.1.304 の回帰）。tool search 抜きで再試行する
- 修正: `modelOverrides` の値と大文字小文字や `[1m]` タグが違うと `/effort`、`/autocompact` が効かない問題
- 修正: cloud session／SDK の `setMcpServers` で渡した MCP サーバーが、後から同名の自分の設定のサーバーに置き換わる問題
- 修正: compaction で古いメッセージを要約から外したことを cloud session とチームメイトが Claude に伝えない問題
- 修正: Workflow の resume が完了済みの `pipeline()`／`parallel()` の agent を再実行する問題（journal から返す）
- 修正: bare リポジトリの新規 worktree が既定ブランチでなくローカル HEAD から始まることがある問題、変更の無い subagent worktree が掃除されない問題
- Self-hosted runner: `TERM` 設定時に stdout だけ共有する起動スクリプトが失敗（2.1.300 の回帰）、`GIT_CONFIG` で設定を読む git credential helper／askpass でリポジトリアクセスが失敗（2.1.296 から）、背景に残る runner で spawn-runner フックがタイムアウト扱いになる問題を修正
- [Cloud sessions] Cloud environments の管理画面が既存環境の保存を誤って拒否する問題を修正。self-hosted environment の削除ダイアログが妨げる要因と影響を示す
- [Claude Tag] 管理画面の Add で、Claude が未参加の公開 Slack チャンネルを検索できる。access bundle で別 GitHub アカウントに移ったリポジトリを再追加できる。Slack スレッドの routine が会話再開後に投稿されない問題、会話終了後に成功と報告して投稿しない問題（スキップして作成者に通知）を修正
- [Code Review] 複数 push が重なると最新コミットをレビューしないことがある問題を修正。再レビューは、以前のブロッキング指摘が未解決の間は LGTM で始めない
- [VSCode] SessionStart／Setup フック実行中の "Running start-up hooks" スピナー（スクリーンリーダー対応）ほか
- その他の修正・改善（screen reader、起動時警告、Remote Control のメッセージなど）が約15件

### 2.1.304
- mods: プラグインが先に走って mod のフックを飛ばしたとき、transcript に行を追加。`tool.check` の答えに `decider: "person"`（許可ダイアログかホストのコールバックだけが承認でき、誰にも聞けない環境では mod の理由つきで拒否）。`tool.check` イベントに `e.isReadOnly`
- 変更: mods の `settings.read` フックが各 settings 層を受け取り、マージ後の設定を書き換えられる。managed mod が組織の設定を上限にでき、保持期間の掃除が使う `cleanupPeriodDays` も対象
- 変更: mods を有効にする質問をリンクとセッション ID なしの平文にした。mod の修正（リロード失敗で前の版のツールが消える問題、同ラベルでキーなしのボタンのクリック消失）を修正。VS Code のチャットパネルで、Bedrock、Vertex、Foundry、LLM ゲートウェイ、テレメトリ無効のセッションでも mod を描画。`claude plugin validate` から、mod のフックの実行場所を予測する注記を削除
- 追加 `/auto-mode-setup`: プロジェクトと最近のセッションを読んで auto mode に環境を教える。Bedrock、Vertex、Foundry、Claude apps gateway、テレメトリ無効のセッションでも使える
- 追加 `/claude-api managed-agents-secure`: Managed Agents の agent の設定を Anthropic 公開のセキュリティガイドと比較（変更はしない）。`/claude-api` スキルは Claude Platform on AWS で SDK や curl でなく `ant` CLI を使う
- 追加: Pro／Max で非アクティブな会話を再開すると 5 時間枠を大きく使う場合の警告
- 変更: カスタム `ANTHROPIC_BASE_URL` 配下で tool search を既定オン（ゲートウェイの 400／422 は tool search 抜きで再試行）。`context_management: Extra inputs are not permitted` のゲートウェイ配下では、そのフィールドを外して再送
- 変更: compaction 後にスキル一覧を再送。`/reload-skills` は新規・変更のスキルだけ送る。skill hooks は 1 ソース（リポジトリ、自分のフォルダ、プラグイン）につき 1 セッション最大 1,024 フック・マッチャー文字 16,384
- 変更: フックをプラグイン限定にするポリシー下で、フックが除外されたスキルは `allowed-tools` を得ない
- 変更: `/fast` ダイアログの Opus 5.5 で "(research preview)" ラベルを削除
- 修正（安全関連）: `sandbox.filesystem.denyRead` のグロブに文字クラスでない角括弧（`[user-id]` など）があると Linux でサンドボックスのコマンドが起動しない問題。`rm -r` でマウント済みドライブやトップレベルフォルダ（`/Volumes`、`/media`、WSL の `/mnt/c`）に安全確認が出ない問題。`claude --worktree` が HEAD の切り離し時などに確認なしで worktree とブランチを消し、コミットを失いうる問題
- 修正: `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` が黙って 100K 窓になる問題（`k`、`M` の接尾辞を受け付け、範囲外は警告）。`/effort status` などが `CLAUDE_CODE_EFFORT_LEVEL` が `auto`／`unset` のときに推測値を表示する問題。1 時間上限の `/loop` wakeup がプロンプトキャッシュ失効直後に走る問題
- 修正: 組織ポリシーが `ANTHROPIC_API_KEY` 承認後の時間ごとの確認まで更新されない問題。server-managed settings の OpenTelemetry 設定が初回セットアップ後に無視される問題。plugin が `--max-turns`／Stop を越えて headless を続ける問題。agent teams で shutdown 承認が CLI 全体を終了させる問題
- 改善: subagent 多数時の応答性と throughput、長い会話のメモリ、auto mode のセッションファイルサイズ（分類器の文脈を毎リクエスト保存しない）、resume の高速化
- [Code Review] review levels: Owner が組織に Quick／Standard（既定）／Deep を選び、リポジトリごとにも設定できる。管理設定に、GitHub 組織の全リポジトリ（後から追加も含む）をレビューする選択肢。有効化直後 1〜2 分の PR がスキップされる問題を修正（再試行）
- [Claude Tag] チャンネルが Enterprise Grid の複数 workspace に共有されると黙る問題、スレッド外の `@Claude !fork` に反応がない問題を修正
- [VSCode] background sub-agent を Agent カードの下に 1 行で表示（全文は /tasks）。SessionStart コマンドフックの時間を 60000ms の初期化制限から除外（合計最大 10 分）ほか
- [Cloud sessions] 新規会話の最初のターンは、claude.ai から同期したプラグインのローカル（stdio）MCP サーバーを待たない（`alwaysLoad: true` の場合を除く）
- その他の修正・改善が約35件
